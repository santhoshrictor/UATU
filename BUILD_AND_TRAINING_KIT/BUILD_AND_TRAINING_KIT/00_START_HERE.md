# Build and training kit

This kit gives a coding assistant a complete project contract and gives you a practical data-preparation workflow. It contains planning materials and templates, not a trained model, installed annotation service, or completed application.

**Use it in this order**

1. Copy/extract the kit into the new project folder you want to use. Preserve the reference/ and templates/ subfolders.
2. Open that folder in your coding editor. If using a chat interface, attach the relevant individual files; use the archive only if the interface can inspect archives.
3. Fill in 03_SITE_BRIEF_TEMPLATE.md. Unknown values may remain unknown. Keep credentials out of it.
4. Read 02_DATA_UPLOAD_AND_TRAINING_GUIDE.md to decide which files belong in coding context, private datasets, runtime configuration, or protected secrets.
5. Paste the entire content of 01_MASTER_BUILD_PROMPT.md into the coding assistant. Tell it where this project folder is. The reference files already include the original PDF, requirements analysis, and complete build plan.
6. Supply camera/interface documents and permitted footage incrementally. Do not upload bulk private footage to a hosted chat simply because it supports attachments.
7. Use an approved annotation tool to create reviewed labels. Use 04_MODEL_TRAINING_PROMPT.md for a selected model when data and training resources are ready.
8. Require actual tests, failure/recovery checks, model evaluations, and the site pilot before accepting production claims.

**A short launcher if the full prompt is already accessible as a file**

Read and follow 01_MASTER_BUILD_PROMPT.md as my build request. Read its referenced requirements, build plan, completed site brief, and data guide. Begin implementing the new application in this workspace using the ordered stages and acceptance gates. Keep a truthful feature status and continue independent work when hardware or data is missing. Do not claim live integration, trained models, or production acceptance without evidence. Start with the requirement register, runnable foundation, recording, permissions, and one complete camera-to-incident workflow.

**What to provide now**

The bundled documents plus the completed brief are enough to start coding. Add permitted representative recordings if you have them, with source/time metadata. If you still have no camera, arrange one for physical connectivity tests while development continues. Full industrial acceptance requires actual cameras, required gateways, representative unseen data, suitable hardware, and trained site responders.

**Files**

- 01_MASTER_BUILD_PROMPT.md: full implementation instruction.
- 02_DATA_UPLOAD_AND_TRAINING_GUIDE.md: what to collect, where to put it, labeling, splits, training, validation, deployment.
- 03_SITE_BRIEF_TEMPLATE.md: editable project decisions and missing inputs.
- 04_MODEL_TRAINING_PROMPT.md: model-specific development and evaluation instruction.
- templates/: editable custom metadata examples; see its README before use.
- reference/: original requirements and the two detailed reports.
